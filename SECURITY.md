# Security policy

## Reporting a vulnerability

Please **do not open a public issue**. Report it privately through GitHub's [private vulnerability reporting](https://github.com/Shubhankart101/India-s-Journey/security/advisories/new). Include the steps to reproduce and the impact. We aim to acknowledge reports within 7 days.

## Scope

- The Django + React web app (`webapp/`, `frontend/`), including sign-in, sessions, saved charts and the API.
- The GitHub Actions workflows and the Terraform samples.
- The static GitHub Pages site (`docs/`). It is read-only and has no server side.

## Security design

- **No local passwords for site users.** Sign-in uses Google or Microsoft OAuth (authorization code with PKCE, `state`, minimal scopes) and starts with a POST that requires CSRF. Provider tokens are not stored. A Microsoft login with an unverified email is never linked to an existing account. See [docs/AUTHENTICATION.md](docs/AUTHENTICATION.md).
- **Sessions:** cookie-based. In production, the session and CSRF cookies are `Secure`, the session cookie is `HttpOnly`, and both use `SameSite=Lax`. Every unsafe API method requires CSRF.
- **Headers:** `X-Frame-Options: DENY`, `nosniff` and a strict referrer policy. `/api/health/` is the only endpoint that allows cross-origin reads.
- **Input:** API filters are validated, page size is capped, and redirect targets (`next`) must stay on this site.
- **Secrets** live in Render or GitHub settings, or in Terraform variables and remote state. Never commit them. `DJANGO_SECRET_KEY` is generated by the platform.
- **Errors:** production never renders debug pages. Error responses include only a short message and the backup links.
- **Dependencies:** pinned in `webapp/requirements.txt` and `frontend/package-lock.json`.
